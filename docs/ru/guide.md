## Установка

```bash
npm install @rwcjs/core
```

Пакет — ESM. Собирается любым бандлером (Vite, Rspack, webpack, esbuild, bun).
Отдельного компилятора шаблонов или плагина к редактору не нужно: разметка —
обычный TypeScript.

## Первый компонент

```ts
import { defineComponent, div, span, useCustomComponent } from "@rwcjs/core";

class Hello extends defineComponent({
  props: { name: "мир" },
}) {
  render() {
    return div({}, "привет, ", span(this.props.name));
  }
}

export const hello = useCustomComponent(Hello, "x-hello");
```

`defineComponent` собирает базовый класс: из ключей `props` получаются сигналы и
список наблюдаемых атрибутов, из ключей `events` — эмиттеры. Наследник обязан
реализовать `render()`. Вернуть можно элемент, фрагмент (например, от `when`) или
массив узлов — корневая обёртка не обязательна.

`useCustomComponent` регистрирует тег и возвращает фабрику:

```ts
document.body.append(hello({ ".name": "rwc" }));
// <x-hello> с shadow root внутри
```

## Сигналы

Сигнал — функция-значение с методом записи.

```ts
import { signal } from "@rwcjs/core";

const count = signal(0);

count();                        // 0 — чтение (и подписка, если внутри эффекта)
count.set(1);                   // запись
count.update((prev) => prev + 1); // запись от предыдущего значения
count.peek();                   // 2 — чтение без подписки
```

Запись синхронная: после `set` зависимая разметка уже обновлена, никаких
микрозадач ждать не нужно.

Одинаковое значение подписчиков не будит. Сравнение по умолчанию — `Object.is`,
его можно заменить:

```ts
// Массив мутируется на месте и записывается той же ссылкой — сравнение мешает.
const items = signal<string[]>([], { equals: false });

// Своё сравнение: точка «та же», пока совпадают координаты.
const point = signal({ x: 0, y: 0 }, { equals: (a, b) => a.x === b.x && a.y === b.y });
```

### batch

Несколько записей подряд будят подписчиков по разу на каждую. `batch` схлопывает
их в один прогон:

```ts
import { batch } from "@rwcjs/core";

batch(() => {
  firstName.set("Ада");
  lastName.set("Лавлейс");
}); // подписчики обоих сигналов выполнятся здесь, один раз
```

`computed`, прочитанный внутри `batch`, уже актуален: он пересчитывается при
чтении, не дожидаясь конца группы.

## Эффекты

Эффект выполняется сразу и потом при каждом изменении того, что он прочитал.
Зависимости собираются автоматически и пересобираются на каждом прогоне.

```ts
import { effect, onCleanup, signal } from "@rwcjs/core";

const seconds = signal(0);

const ticker = effect(() => {
  const id = setInterval(() => seconds.update((n) => n + 1), 1000);
  onCleanup(() => clearInterval(id));
});

ticker.destroy(); // остановит таймер: onCleanup выполнится
```

`onCleanup` выполняется перед каждым следующим прогоном и при уничтожении.
`onDispose` — только при уничтожении, регистрируется на первом прогоне:

```ts
effect(() => {
  const controller = new AbortController();
  onCleanup(() => controller.abort()); // на каждый перезапуск

  onDispose(() => console.log("эффект больше не нужен")); // один раз, в конце
});
```

### Условные зависимости

Зависимости пересобираются, поэтому ветка условия подписывается корректно:

```ts
effect(() => {
  // Пока useA() истинно, изменения b эффект не будят.
  console.log(useA() ? a() : b());
});
```

### Вложенные эффекты

Эффект, созданный внутри прогона другого, становится его ребёнком: умирает при
перезапуске родителя и создаётся заново. Эффекты не накапливаются, а уничтожение
родителя каскадом уносит всё поддерево.

```ts
effect(() => {
  const user = currentUser();

  // Своя подписка на каждого пользователя; при смене user старая уйдёт.
  effect(() => console.log(user, notificationsFor(user)()));
});
```

Если вложенный эффект должен пережить перезапуск родителя, разорвите владение
через `untracked`:

```ts
effect(() => {
  trigger();
  untracked(() => effect(() => /* живёт сам по себе */ null));
});
```

### untracked

Читает без подписки:

```ts
effect(() => {
  const shown = visible();                  // зависимость
  const theme = untracked(() => currentTheme()); // не зависимость
});
```

Для разового чтения одного сигнала короче `peek()`.

### Защита от цикла

Эффект, который пишет в сигнал, от которого сам зависит, зациклился бы навсегда.
Такой случай прерывается ошибкой, а не подвисанием страницы:

```ts
effect(() => count.set(count() + 1));
// Error: [rwc] infinite loop in effects: an effect writes to a signal it depends on
```

Обычно лечится `peek()` или `update()` — они читают без подписки.

## Производные значения

Два способа, оба возвращают источник, который можно читать и передавать дальше.

```ts
import { computed, derived } from "@rwcjs/core";

// Ленивый и с запоминанием: вычисляется при чтении, пересчитывается,
// только когда зависимости действительно изменились.
const total = computed(() => price() * quantity());

// Не запоминает: compute выполняется на каждое чтение.
const label = derived(() => `${price()} ₽`);
```

Берите `computed` для тяжёлых вычислений и для значений, которые читают из
нескольких мест; `derived` — для дешёвых выражений.

`computed` ленивый: пока его никто не читает, он ничего не вычисляет. Запись в
источник лишь помечает его устаревшим; значение пересчитается при следующем
чтении и только если источник действительно изменился. Если новое значение равно
старому (`Object.is` или опция `equals`), наблюдатели не просыпаются:

```ts
const isAdult = computed(() => age() >= 18);
effect(() => console.log(isAdult())); // не перезапускается, когда age меняется с 30 на 31
```

Промежуточных состояний эффекты не видят. В ромбе `a → (b, c) → d` эффект на
`d` выполнится один раз и получит `b` и `c` уже согласованными, сколько бы
уровней `computed` ни лежало между ними.

На источники `computed` подписан, лишь пока его читает какой-нибудь эффект.
Владелец ему не нужен и утечки нет, поэтому объявлять его можно где угодно — в
`render()`, в модуле, в сторе.

Дополнительно:

```ts
import { combine, rs } from "@rwcjs/core";

const size = rs`btn btn-${sizeSignal}`;      // реактивная строка
const both = combine(width, height);          // кортеж значений
const [w, h] = both();
```

## Разметка

Каждому тегу соответствует фабрика. Первый аргумент — необязательный конфиг,
дальше идут дети.

```ts
import { a, button, div, input, span } from "@rwcjs/core";

div(
  { class: "card" },
  span("заголовок"),
  button({ "@click": () => console.log("клик") }, "жми"),
);

div("только текст");  // конфиг можно не передавать
```

### Ключи конфига

| Ключ | Что делает |
| --- | --- |
| `.свойство` | пишет в DOM-свойство элемента |
| `@событие` | вешает слушатель |
| `class` | классы: строка, массив, объект условий, `cls` |
| `attrs` | произвольные атрибуты: `data-*`, `aria-*`, `role` |
| `style` | инлайновые стили, в том числе CSS-переменные |
| `show` | переключает видимость через `display` |

```ts
input({
  ".value": text,                       // свойство, а не атрибут
  ".disabled": () => text().length > 20,
  "@input": (event) => text.set(event.currentTarget.value),
  class: ["field", { invalid: hasError }],
  attrs: { "aria-invalid": hasError, "data-role": "search" },
  style: { "--field-hue": hue },
  show: visible,
});
```

Точка означает именно свойство: значение пишется прямо в объект элемента, минуя
сериализацию в строку. Для `data-*`, `aria-*` и всего, чему нужен атрибут,
есть `attrs`.

Обработчик события получает точный тип: у `@input` на `<input>` это `InputEvent`,
а `currentTarget` типизирован конкретным элементом.

### Реактивность в разметке

Там, где значение не может быть функцией, **любая функция считается реактивным
источником**. Сигнал и обычная функция равнозначны:

```ts
span(count);                    // сигнал
span(() => count() * 2);        // выражение
div({ attrs: { title: () => user().name } });
div({ style: { width: () => `${percent()}%` } });
```

Реактивным становится только сам узел: меняется текст, свойство или атрибут,
а не поддерево.

У пропсов веб-компонентов правило другое: там значение вполне может быть
функцией (например, проп-шаблон), поэтому реактивный источник обязан быть
сигналом:

```ts
tabs({ ".renderTab": (tab) => span(tab.title) }); // функция — это значение
tabs({ ".active": activeSignal });                 // сигнал — это источник
```

### Дети

Детьми могут быть строки, числа, узлы и реактивные источники. `null`, `undefined`
и `false` пропускаются — работает привычное `условие && разметка`:

```ts
div({}, "счёт: ", count, isAdmin() && span("админ"));
```

### Классы

```ts
import { cls } from "@rwcjs/core";

div({ class: "card" });
div({ class: ["card", "wide"] });
div({ class: ["tab", { active: isActive, disabled: () => !enabled() }] });

div(cls`card`);                             // класс — единственный ключ конфига
div(cls`btn btn-${size}`);                  // btn-lg одним токеном
div({ ...cls`card`, ".id": "main" });        // вместе с другими ключами
```

`cls` — тот же конфиг, только записанный короче. В примерах и на стенде правило
простое: **в конфиге кроме класса ничего нет — `cls`; есть что-то ещё — объектная
форма**. Спред `{ ...cls`...` }` нужен редко: он длиннее обычного ключа `class`
и оправдан разве что вместе со склейкой интерполяции.

Каждый источник владеет только своими токенами: если два источника дают один и
тот же класс, снятие одним не убирает его, пока держит второй. Токен, который
остаётся в обоих состояниях, не покидает `classList` даже на мгновение — иначе
перезапускались бы CSS-переходы.

## Управление потоком

### when

Условный рендер. Ветка пересобирается только при смене истинности условия.

```ts
import { when } from "@rwcjs/core";

div(
  {},
  when(isLoggedIn, () => profile(), () => loginForm()),
);
```

Содержимое снятой ветки уничтожается вместе со своими эффектами.

### show

Прячет элемент через `display`, оставляя DOM, состояние и эффекты живыми:

```ts
div({ show: isOpen }, heavyContent());
```

Берите `show`, когда переключение частое, а содержимое дорого пересобирать;
`when` — когда содержимое должно исчезнуть по-настоящему.

### each

Списки с переиспользованием узлов по ключу. В рендер приходят **сигналы**
элемента и индекса:

```ts
import { each } from "@rwcjs/core";

ul(
  {},
  each(
    users,
    (user, index) => li({}, () => `${index() + 1}. ${user().name}`),
    (user) => user.id,   // ключ; по умолчанию — сам элемент
  ),
);
```

При обновлении списка узлы переиспользуются: смена данных меняет содержимое
сигналов, а не пересоздаёт разметку. Перестановка двигает минимум узлов —
элементы, стоящие в правильном относительном порядке, остаются на месте. Где
браузер умеет `Element.moveBefore()`, перемещение атомарно: компоненты не
отключаются, а фокус и состояние `iframe` и `video` сохраняются.

Ключ по умолчанию — сам элемент, что годится для примитивов. Для объектов
передавайте `getKey`, иначе записи будут пересоздаваться на каждое обновление
(библиотека об этом предупредит).

### dynamic

Полностью реактивный участок: пересобирается при изменении любого сигнала,
прочитанного прямо в теле.

```ts
import { dynamic } from "@rwcjs/core";

div({}, dynamic(() => (user() ? profile(user()) : loginForm())));
```

`dynamic` дороже `when`: он собирает разметку заново. Берите его, когда меняется
сама структура, а не одно значение.

Ни `when`, ни `each`, ни `dynamic` не оборачивают содержимое в дополнительный
элемент — место в DOM держат комментарии-якоря, поэтому `ul > li`, `:nth-child`
и раскладки grid/flex работают как обычно.

## Компоненты

```ts
class Field extends defineComponent({
  props: { value: "", label: "", disabled: false },
  events: { valueChange: payload<string>(), submit: payload<void>() },
  eventOptions: { submit: { bubbles: false } },
  shadow: "open",
  styles: css`:host { display: block }`,
}) {
  render() {
    return label(
      {},
      this.props.label,
      input({
        ".value": this.props.value,
        ".disabled": this.props.disabled,
        "@input": (event) => {
          this.props.value.set(event.currentTarget.value);
          this.events.valueChange(event.currentTarget.value);
        },
      }),
    );
  }
}
```

### Пропсы

Начальные значения задают и типы, и список наблюдаемых атрибутов. Ключ
`maxCount` соответствует атрибуту `max-count`.

Два пути записи:

```ts
field({ ".value": "текст" });   // прямо в сигнал: любые типы, без сериализации
element.setAttribute("value", "текст"); // через атрибут: разбирается по типу пропса
```

Атрибут — всегда строка, поэтому он разбирается по типу начального значения
пропса:

- `boolean` — как в HTML: атрибут есть, значит `true` (`<x-switch disabled>`);
  `"false"` и снятый атрибут дают `false`;
- `number` — `Number()`; нечисло или пустая строка откатываются к начальному
  значению;
- `string` — строка как есть: `label="42"` остаётся `"42"`;
- всё остальное (объекты, массивы, `null`) — JSON, а что не разобралось —
  остаётся строкой.

Снятие атрибута возвращает небулев проп к начальному значению.

Реактивный проп связывает родителя с ребёнком:

```ts
field({ ".value": nameSignal }); // эффект принадлежит родителю
```

### События

Ключ `valueChange` даёт событие `value-change`. Payload описывается через
`payload<T>()` — это только тип, в рантайме ничего не создаётся.

```ts
this.events.valueChange("новое");  // dispatchEvent(new CustomEvent("value-change", { detail }))
```

По умолчанию события всплывают и пересекают границу shadow
(`bubbles: true, composed: true`); `eventOptions` это меняет.

Слушать можно и через конфиг фабрики, и обычным `addEventListener`:

```ts
field({ "@valueChange": (event) => console.log(event.detail) }); // detail типизирован
element.addEventListener("value-change", handler);
```

### Отражение пропсов в атрибуты

Стили часто зависят от состояния: `:host([disabled])`. `reflect` зеркалит пропсы
в атрибуты хоста:

```ts
class Chip extends defineComponent({
  props: { disabled: false, variant: "plain" },
  reflect: ["disabled", "variant"],
  styles: css`:host([disabled]) { opacity: 0.5 }`,
}) { ... }
```

`true` превращается в пустой атрибут, `false`/`null`/`undefined` его снимают,
строки и числа пишутся как есть, объекты — JSON. Отражение включается при
подключении элемента, а не в конструкторе. Атрибут и проп не зацикливаются:
атрибут разбирается обратно в то же значение. На классе то же самое —
`static reflect`.

### Формы

`form: true` делает компонент участником форм: его значение попадает в
`FormData`, работают валидация, сброс формы и `disabled` у `fieldset`.

```ts
class Rating extends defineComponent({ props: { value: 0 }, form: true }) {
  render() {
    this.setFormValue(() => String(this.props.value()));
    return button(
      { ".disabled": this.formDisabled, "@click": () => this.props.value.update((n) => n + 1) },
      this.props.value,
    );
  }
}
```

- `setFormValue(value)` — с сигналом или функцией держит `FormData` в
  актуальном состоянии; вызывайте в `render()`.
- `internals` — `ElementInternals`: `setValidity`, `states`, `form`, `labels`.
  Без `form: true` бросает ошибку.
- `formDisabled` — сигнал, `true`, пока отключены `fieldset` или форма выше.
- `formReset()` — защищённый хук сброса формы; по умолчанию возвращает все
  пропсы к начальным значениям. Переопределите, если сброс должен делать другое.

Полный пример — в [рецептах](./recipes.md#поле-ввода-для-формы).

### Жизненный цикл

`render()` вызывается при подключении к DOM. Все эффекты, созданные во время
рендера — реактивные дети, свойства, атрибуты, классы, `resource` — принадлежат
компоненту и уничтожаются при отключении вместе с разметкой. `computed` никому не
принадлежит: когда эффекты компонента умирают, он просто перестаёт быть подписан
на источники. При повторном подключении компонент рендерится заново.

Уборка идёт на микрозадаче, а не внутри `disconnectedCallback`. Если элемент
вставили обратно в том же такте — передвинули через `insertBefore`, переставили
в `each`, перенесли в портал, — ничего не перерисовывается: фокус, введённый
текст и скролл остаются. Атомарные перемещения через `moveBefore()` обрабатывает
`connectedMoveCallback`, и компонент вовсе не отключается.

В тестах это значит, что сразу после `remove()` уборки ещё не видно:

```ts
element.remove();
await new Promise((resolve) => setTimeout(resolve, 0));
expect(element.shadowRoot!.textContent).toBe(""); // уборка прошла
```

Ручная уборка не нужна: таймеры и подписки вешаются на `onCleanup` внутри
эффекта и уходят вместе с ним.

### Теневой корень

По умолчанию `open`: до внутренностей можно добраться из тестов и отладчика.
Закрытый режим — явным флагом:

```ts
defineComponent({ props: {}, shadow: "closed" });
defineComponent({ props: {}, shadow: { mode: "open", delegatesFocus: true } });
```

## Стили

CSS объявляется на классе и разбирается один раз на всю страницу — экземпляры
делят один `CSSStyleSheet` через `adoptedStyleSheets`:

```ts
import { css } from "@rwcjs/core";

class Card extends defineComponent({ props: {} }) {
  static override styles = css`
    :host { display: block; border: 1px solid var(--card-border, #ddd) }
    .title { font-weight: 600 }
  `;

  render() {
    return div(cls`title`, "заголовок");
  }
}
```

Массив тоже работает — удобно для общей базы:

```ts
defineComponent({ props: {}, styles: [BASE, CARD] });
```

Стили страницы внутрь shadow root не проникают, а CSS-переменные наследуются:
это и есть штатный способ темизации снаружи.

## Слоты

### Нативные

Обычный `<slot>` работает без спецмеханики — содержимое едет в светлый DOM хоста:

```ts
class Panel extends defineComponent({ props: {} }) {
  render() {
    return div(cls`panel`, slot(), slot({ ".name": "footer" }));
  }
}

panel({}, div("тело"), div({ attrs: { slot: "footer" } }, "низ"));
```

### Со своим контекстом

Когда родительский шаблон должен получить данные компонента, объявите слоты
с типом контекста:

```ts
class Table extends defineComponent({
  props: { rows: [] as Row[] },
  slots: {
    row: payload<{ row: ReadonlySignal<Row>; index: ReadonlySignal<number> }>(),
    empty: payload<void>(),
  },
}) {
  render() {
    return when(
      () => this.props.rows().length > 0,
      () =>
        ul(
          {},
          each(
            this.props.rows,
            (row, index) => this.renderSlot("row", { row, index }, () => li(() => row().name)),
            (row) => row.id,
          ),
        ),
      () => this.renderSlot("empty", undefined, () => p("пусто")),
    );
  }
}
```

Родитель передаёт шаблоны ключами `#имя`:

```ts
table({
  ".rows": rows,
  "#row": ({ row, index }) => li({}, () => `${index()}: ${row().name}`),
  "#empty": () => p("ничего не нашлось"),
});
```

Контекст типизирован: `row` и `index` в шаблоне выведены из объявления. Третий
аргумент `renderSlot` — содержимое по умолчанию, когда шаблон не передали.

Контекст обычно состоит из сигналов: тогда шаблон обновляется вместе с данными,
а узлы не пересоздаются.

## Контекст

Значение, доступное всему поддереву без проброса пропсов.

```ts
import { createContext } from "@rwcjs/core";

export const ThemeKey = createContext<"light" | "dark">("theme", "light");
```

Второй аргумент — значение по умолчанию. Без него в тип попадает `undefined`,
и потребитель обязан этот случай обработать.

```ts
class App extends defineComponent({ props: {} }) {
  render() {
    const theme = signal<"light" | "dark">("dark");
    this.provide(ThemeKey, theme);       // можно и статикой: this.provide(ThemeKey, "dark")
    return div({}, toolbar());
  }
}

class Toolbar extends defineComponent({ props: {} }) {
  render() {
    const theme = this.inject(ThemeKey); // сигнал: обновится вместе с провайдером
    return div({ class: ["bar", { dark: () => theme() === "dark" }] });
  }
}
```

Поиск идёт вверх по дереву, пересекая границы shadow, и находит ближайшего
провайдера. Работает и для содержимого слотов — оно тоже потомок хоста.

Значение объявляйте в `render()` провайдера или раньше: потомки читают контекст,
когда подключаются к DOM, то есть уже после того, как `render()` вернул разметку.

## Асинхронность

```ts
import { resource } from "@rwcjs/core";

class Search extends defineComponent({ props: { query: "" } }) {
  render() {
    const found = resource(
      (abort) =>
        fetch(`/api/search?q=${this.props.query()}`, { signal: abort }).then((r) => r.json()),
      { initialValue: [] as Person[] },
    );

    return div(
      {},
      when(found.loading, () => span("ищем…")),
      when(found.error, () => span("не получилось")),
      ul({}, each(() => found.data() ?? [], (person) => li(() => person().name), (p) => p.id)),
      button({ "@click": found.refetch }, "ещё раз"),
    );
  }
}
```

Сигналы, прочитанные внутри `fetcher`, становятся зависимостями: смена запроса
запускает новый. Предыдущий отменяется через `AbortSignal`, а его ответ
игнорируется — гонка «старый ответ поверх нового» исключена. При отключении
компонента запрос отменяется.

Есть и одноразовая реакция на первое изменение:

```ts
import { firstUpdate } from "@rwcjs/core";

// Начальное значение пропускается, срабатывает один раз и отписывается.
firstUpdate(this.props.value, (value) => this.events.touched(value));
```

## Функциональные компоненты

Кусок разметки, которому не нужны ни свой тег, ни теневой корень, ни атрибуты:

```ts
import { createComponent } from "@rwcjs/core";

const Card = createComponent<{ title: string }, HTMLElement>((props, ...children) =>
  section(cls`card`, h3(props.title), ...children),
);

Card({ title: "Отчёт", class: ["wide"] }, p("тело"));
```

Обёртка добавляет к пропсам `class`, `attrs`, `style` и `show` и вешает их на
корневой элемент — вызов выглядит так же, как у обычного тега. Эффекты внутри
принадлежат тому компоненту, в чьём `render()` шёл вызов.

## Код вне компонентов

Эффекты, созданные вне `render()`, некому уничтожить — библиотека об этом
предупредит. Для точки входа, модульного состояния и тестов есть корневой
владелец:

```ts
import { createRoot } from "@rwcjs/core";

const app = createRoot(() => div({}, header(), counter({ ".value": total })));
document.getElementById("app")!.append(app);
```

Если нужно уметь всё это уничтожить, возьмите `dispose` первым аргументом:

```ts
const app = createRoot((dispose) => {
  onSignOut(dispose);
  return div({}, dashboard());
});
```

## Регистрация и версии

`useCustomComponent` регистрирует сразу. Когда момент регистрации важен —
разделите объявление и регистрацию:

```ts
import { configCustomComponent } from "@rwcjs/core";

export const [UwcButton, registerUwcButton] = configCustomComponent(Button, "uwc-button");
```

Приложение решает, под каким тегом компонент появится:

```ts
registerUwcButton();                       // <uwc-button>
registerUwcButton({ postfix: "moduleA" }); // <uwc-button-modulea>
```

Вызовы фабрики при этом не меняются:

```ts
UwcButton({ ".type": "primary" }, "Нажми");
```

Так две версии UI-кита уживаются на одной странице: каждая сборка регистрирует
свои теги со своим постфиксом, а прикладной код остаётся прежним. Один класс
можно зарегистрировать только под одним тегом — это правило `customElements`,
поэтому разные версии обязаны быть разными сборками.

## Как это устроено

**Владение эффектами.** Пока идёт `render()`, библиотека знает текущего
владельца — компонент, в чьём рендере мы находимся. Каждый эффект, созданный в
это время, записывается на него. Искать владельца по DOM нельзя: во время
рендера узлы ещё не вставлены.

Блоки `when`, `each` и `dynamic` заводят собственные скоупы: содержимое,
собранное внутри, уничтожается вместе с веткой или записью списка.

**Очередь.** Запись в сигнал складывает подписчиков в очередь и тут же её
разбирает. Очередь — множество, поэтому эффект, до которого ведут два пути,
выполнится один раз. `batch` откладывает разбор до выхода из группы.

**Ленивый computed (push-pull).** Запись ничего не пересчитывает: она помечает
`computed` ниже по цепочке как возможно устаревшие и ставит в очередь эффекты за
ними. Перед прогоном эффект дотягивает свои `computed`-источники; если ни один
из них на деле не сменил значение, прогон пропускается. Поэтому нет ни
промежуточных состояний, ни лишних прогонов.

**Дерево эффектов.** Вложенный эффект — ребёнок того, в чьём прогоне он создан.
Перед каждым перезапуском родитель уничтожает детей, а при уничтожении уносит
всё поддерево. Поэтому `dynamic` внутри `each` внутри компонента убирается за
собой на любом уровне.

**Списки.** `each` сопоставляет старые и новые записи по ключу, а порядок
приводит к нужному, двигая только те узлы, что действительно не на месте:
позиции, уже образующие правильный относительный порядок, ищутся как наибольшая
возрастающая подпоследовательность.
