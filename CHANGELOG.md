# Список изменений

## [2.15.1]

### Добавлено
#### signalComponent
```typescript
function signalComponent<T extends ExtraHTMLElement>(
  cb: () => ComponentConfig<T> | CustomComponentConfig<T>
): ReturnType<typeof cb>
```
Возвращает реактивный компонент без лишней div-обертки.
- **Параметры:**
  - `cb`: Функция обратного вызова, которая возвращает компонент для рендеринга
- **Возвращает:** Реактивный компонент без дополнительной обертки
- **Поведение:**
  - В отличие от `getSignalContent`, не создает дополнительную DOM-обертку
  - Улучшает контроль над версткой и CSS за счет отсутствия лишней вложенности
  - Напрямую заменяет предыдущий элемент на hostElement нового компонента

## [2.14.0]

### Добавлено
- **Работа со слотами**: Улучшен механизм обработки слотов с использованием метода `onConnected` из element-helper.ts
  - Компоненты теперь могут регистрировать колбэки, которые выполняются при подключении к DOM
  - Эти колбэки получают доступ к ссылкам на компонент и родительский элемент
  - Обеспечивает коммуникацию между родительским и дочерним компонентами через содержимое слотов для более динамической композиции UI
  - Пример использования: `.onConnected((self, host) => { /* выполнить действия при подключении */ })`

- **Условный рендеринг**: Добавлены утилиты для условного рендеринга в signal.ts
  - `renderIf`: Статический условный рендеринг на основе булевых условий
    - Синтаксис: `renderIf(условие, контентЕслиИстина, контентЕслиЛожь)`
    - Возвращает контентЕслиИстина, когда условие истинно, иначе возвращает контентЕслиЛожь (или пустую строку)
  - `rxRenderIf`: Реактивный условный рендеринг на основе реактивных сигналов
    - Синтаксис: `rxRenderIf(сигналУсловия, контентЕслиИстина, контентЕслиЛожь)`
    - Автоматически перерисовывает контент при изменении значения сигнала
    - Эффективно обрабатывает обновления DOM, изменяя контент только при изменении условия 

## [2.11.0]

## Добавлено
- Добавлен метод `appendSlotContent()` в класс `BaseElement` для привязки слотов к пользовательским компонентам
- Добавлено свойство `slotContent` в класс `BaseElement` для хранения всех элементов слота
- Улучшена обработка слотов в системе компонентов, позволяющая пользователям библиотеки переопределять метод `appendSlotContent()` для нестандартного управления слотами

## Технические детали
- `slotContent` реализован как объект типа Record, сопоставляющий имена слотов с массивами конфигураций компонентов
- Стандартная реализация `appendSlotContent()` добавляет элементы слота к родительскому элементу компонента
- Эти изменения позволяют пользователям библиотеки настраивать поведение слотов путем расширения метода `appendSlotContent()` в своих компонентах

## [2.0.0]

### Добавлено
#### getSignalContent
```typescript
function getSignalContent(
  cb: () => ComponentContent | ComponentContent[]
): ComponentConfig<HTMLDivElement>
```
Создает реактивный контейнер, который автоматически обновляет свое содержимое на основе изменений сигналов.
- **Параметры:**
  - `cb`: Функция обратного вызова, которая возвращает либо одиночный ComponentContent, либо массив ComponentContent
- **Возвращает:** ComponentConfig для div-элемента, который будет автоматически обновляться при изменении сигналов в callback
- **Поведение:** 
  - Создает div-элемент
  - Устанавливает эффект для отслеживания callback
  - Автоматически очищает и обновляет содержимое при изменении сигналов
  - Обрабатывает как одиночные, так и массивные возвращаемые значения

**Примеры использования:**
```typescript
// Пример 1: Простое обновление текста
const count = signal(0);
const counter = getSignalContent(() => `Счетчик: ${count()}`);

// Пример 2: Динамический список
const items = signal(['item1', 'item2']);
const list = getSignalContent(() => 
  items().map(item => el('div').text(item))
);

// Пример 3: Условный рендеринг
const isVisible = signal(true);
const content = getSignalContent(() => 
  isVisible() ? el('div').text('Видимо') : null
);
```

#### createSignal
```typescript
function createSignal<T>(cb: () => T): ReactiveSignal<T | null>
```
Создает реактивный сигнал, который автоматически обновляется на основе функции обратного вызова.
- **Параметры:**
  - `cb`: Функция обратного вызова, которая возвращает значение типа T
- **Возвращает:** ReactiveSignal, который хранит текущее значение (изначально null)
- **Поведение:**
  - Создает сигнал, инициализированный значением null
  - Устанавливает эффект для отслеживания callback
  - Автоматически обновляет значение сигнала при изменении зависимостей
  - Обеспечивает типобезопасность с помощью generic параметра типа T

**Примеры использования:**
```typescript
// Пример 1: Вычисляемое значение
const a = signal(5);
const b = signal(10);
const sum = createSignal(() => a() + b());

// Пример 2: Фильтрация массива
const items = signal(['apple', 'banana', 'orange']);
const search = signal('');
const filtered = createSignal(() => 
  items().filter(item => item.includes(search()))
);

// Пример 3: Форматирование данных
const user = signal({ name: 'John', age: 25 });
const formatted = createSignal(() => ({
  displayName: `${user().name} (${user().age})`,
  isAdult: user().age >= 18
}));
```
