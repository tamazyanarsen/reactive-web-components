# План: ускорение создания строк

Состояние на 3.3.0 (локальный js-framework-benchmark, Chrome 154, Ryzen 9 5900X):
создание 1000 строк — rwc 50,7 мс, Solid 41,8, vanillajs 39,8. Геометрическое среднее
CPU против vanillajs — 1,23 (между Vue 1,19 и Lit 1,24). Отрисовка у всех примерно
одинаковая, разрыв — в скрипте на каждую строку.

Цена одной строки бенчмарка сейчас: 8 `createElement` и 7 `classList.add`,
комментарий-якорь и массив его узлов, скоуп эффектов, сигнал элемента (4 замыкания
и `Set`), два эффекта (класс `danger` и текст метки) — у каждого замыкание `destroy`,
обёртка `untracked` и `Set` источников, узел селектора (`Set` и замыкание), два
обработчика и два `addEventListener`.

Оценки выигрыша ниже — по разбору кода, не замеры. Каждый шаг мерить отдельно
(baseline и новая версия подряд, 15 прогонов, rwc-dev в форке бенчмарка).

## Без изменения API

1. **Статический класс через `className`.** Нет классов и реактивных источников на
   элементе — одно присваивание вместо разбора в `Set` и `classList.add` на токен.
   ~2–4% на создании, риск минимальный.
2. **Единственный текстовый ребёнок через `textContent`.** `td(String(id))` сейчас идёт
   через вариадический `append`. ~1–2%.
3. **Дешевле эффект.**
   - `destroy` — общий метод, как уже сделано с `notify`;
   - скоуп сам сохраняет и восстанавливает наблюдателя, без обёртки
     `untracked(() => effect(...))`;
   - `Set` подписчиков у сигнала — при первом чтении;
   - сигнал-ребёнок (`a(label)`) — лёгкий подписчик, пишущий в текстовый узел, а не
     полноценный эффект.

   ~5–8% на создании, заметно меньше памяти.
4. **Без якоря-комментария у строки из одного элемента.** Якорем служит сам `tr`: нет
   `createComment`, массива узлов и лишней тысячи узлов в DOM. Создание и очистка,
   ~3–6%. Аккуратно с вложенным `when`, подменяющим корень, — тогда якорь остаётся.

Вместе — ~10–15%, ожидаемое среднее ~1,15.

## С изменением API (всё добавляется, старое продолжает работать)

1. **`list` — `each` без сигнала элемента.** Ключ — сам объект, рендер получает обычное
   значение (как `For` против `Index` в Solid). Экономит сигнал на строку.
   ```ts
   list(rows, (row) => tr(td(String(row.id)), td(a(row.label))))
   ```
   ~3–5% на создании, меньше памяти. Цена — ещё один примитив и объяснение в доках.

2. **Делегирование событий** — один обработчик на документе вместо тысяч на строках.
   - а) глобально, как в Solid: `delegateEvents(["click"])`. Просто, но неявно:
     `stopPropagation` обычного обработчика не остановит делегированный, в shadow DOM
     нужен свой корень;
   - б) явным ключом: `"@click.delegate": () => ...`. Без сюрпризов, нужна вторая
     карта событий в типах;
   - в) обработчик с данными: `"@click": [select, id]` — без замыкания на строку.

   Рекомендация: б + в. ~3–6% на создании, меньше памяти.

3. **Клонирование шаблона** — главный резерв, ~10–20%. vanillajs, Solid и Svelte
   собирают строку одним `cloneNode(true)` и расставляют привязки.
   - а) **плагин сборки** (esbuild / Vite / Bun): вложенные вызовы фабрик со статикой
     компилируются в «шаблон + привязки по путям». Код пользователя не меняется, без
     плагина всё работает как раньше. Лучший для пользователя, самый трудоёмкий
     (статический анализ, типы, откат на рантайм для динамической структуры).
     Бенчмарк шаг сборки разрешает;
   - б) **`template()` в рантайме**: первый вызов записывает структуру, следующие
     клонируют. Структура строки обязана быть одинаковой — условия внутри ломают
     запись, нужны предупреждения и правила;
     ```ts
     const Row = template((row: Row) => tr(...));
     each(rows, (row) => Row(row.peek()), (row) => row.id)
     ```
   - в) теговые шаблоны `` html`<tr>...` `` как у lit — быстро, но против идеи
     «без шаблонов, типизированные фабрики» и без типизации. Не рекомендуется.

4. **Селектор как готовый источник:** `class: { danger: isSelected.of(id) }` вместо
   `() => isSelected(id)` — минус функция на строку, ~1%. Только вместе с остальным.

## Порядок

1. **3.4.0:** все пункты без изменения API + `list` + делегирование (б + в). Ожидание —
   15–25% на создании строк, уровень Vue или ближе к Svelte.
2. **Отдельный проект:** шаблоны — сначала прототип `template()` для замера реального
   выигрыша, затем плагин сборки, если цифры оправдают.
3. После каждого выпуска — обновить реализацию в PR js-framework-benchmark (#2121):
   идиоматичный код библиотеки (`list`, делегирование), без трюков под бенчмарк.
